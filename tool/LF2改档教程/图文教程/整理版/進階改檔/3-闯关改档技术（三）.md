## 计数器设计

可以计数定量次数的事件发生后，由计数器产生结果。

### 单纯的计数器

一次攻击一个动作（每发生一次就计数一次）：

```text
frame 0
bdy: ...
frame 20 next: 21
frame 21 wait: 0 next: 999 hit_a: # hit_d: 50
frame 50
...
```

- hit_a 值决定计数次数。
- 如果攻击力为 0，次数约为 = 500 / hit_a: #。

### 一般的计数器

此为考虑事件可能会同时发生的情形而做修正。设 hit_a 为 1，wait 为 0，取而代之，使用 injury 来代替计数值。

```text
frame 0
bdy: ...
frame 20 next: 21
bdy: ...
frame 21 wait: 0 next: 999 hit_a: 1 hit_d: 50
bdy: ...
frame 50
...
```

动作 0、20、21 均加入 bdy，以防漏掉任何计数。再来是考虑如何定 injury 的值……

**计数 5 个事件发生时：**

先定最小攻击力为 99：

```
( 99 + 1 ) * 5 = 500
```

但如果 5 个事件同时发生：

```
( 99 * 5 + 1 ) = 496 < 500（不会使计数器有动作）
```

故最低攻击力要设为 100：

```
( 100 * 5 + 1 ) = 501（5 个同时发生）
( 100 + 1 ) * 5 = 505（不同时发生）
( 100 + 1 ) * 4 = 404（4 次的时候不会有动作，5 次满才有反应）
```

**考虑 20 个事件发生时：**

```
同时发生     ( 25 * 20 + 1 ) = 501
不同时发生   ( 25 + 1 ) * 20 = 520
            ( 25 + 1 ) * 19 = 495（19 次时还不会有反应）
```

**考虑 25 个事件发生时：**

```
同时发生     ( 20 * 25 + 1 ) = 501
不同时发生   ( 20 + 1 ) * 25 = 525
            ( 20 + 1 ) * 24 = 504（超过 500，意即 24 次就有反应，有错误）
```

故同时发生不可计数超过 20 个。不过还是有解决方法，那就是一开始就先把计数器的血量加上去，就可以解决这个问题了（上式计算为 hp 500 的默认情形下）。

## 闯关的 wpoint 使用

在 stage 中，除了玩家角色及电脑角色，到下一阶段时都会从场上被清掉（非玩家控制且 type 不是 0）。另外一点就是手持武器也可以带到下一阶段，利用这一点就可在闯关里做些特效。

假如一个物件 id 400：

```text
frame 0 next: 1
frame 1 next: 2
wpoint: kind: 1
opoint: kind: 2 oid: 400
frame 2 next: 0
wpoint: kind: 1 weaponact: 15
...
frame 15 next: 999
wpoint: kind: 2
```

一开始，一个动作 2 的物件持着动作 15 的物件。红色的 `next: 999` 指闯关到达下一阶段时，就会跳回动作 0（因为一开始持着它的物件被清掉了）。

那就拿我以前做的**假人质**为例吧，也是说 criminal 被攻击后变成敌人，而非我方：

**criminal（id: 300 type: 5）：**
