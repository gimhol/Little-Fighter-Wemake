## state 80## 之 pic 编码的变化

我们可在 criminal 中发现闯关人质使用 state: 80## 变身成 id ## 的人物，但用在别的角色图片却会跑掉（注意：在 knight 身上不适用，因 knight 在战争模式显示是正常的）。于是我们开启 bandit 求解：

```text
file(0-69):   sprite\sys\bandit_0.bmp  w: 79  h: 79  row: 10  col: 7
file(70-139): sprite\sys\bandit_1.bmp  w: 79  h: 79  row: 10  col: 7
file(140-209): sprite\sys\bandit_0b.bmp w: 79  h: 79  row: 10  col: 7
file(210-279): sprite\sys\bandit_1b.bmp w: 79  h: 79  row: 10  col: 7
```

'b' 指蓝队。可发现 b 图从 140 开始，也就是说之下的每个 frame 中的 pic 数值会加上 140，全都换到 b 图。

> [!NOTE]
> 这些定格图的编号是由 row、col 编排的，并非 file(#-#) 这两组数字。`row: 10 col: 7` 指这张图被划分成 7 列 10 栏（此改档的英文用法不一样）。

**练习题：**

咱取 weapon0 的档案：

```text
file(0-99): sprite\sys\weapon0.bmp  w: 48  h: 48  row: 10  col: 10
```

假如有 state: 8100 变身成 stick 时，weapon0 的图应该怎么改？

**解答：**

```text
file sprite\sys\weapon0.bmp  w: 48  h: 48  row: 10  col: 14
file sprite\sys\weapon0.bmp  w: 48  h: 48  row: 10  col: 4
```

## 抓人之位置变化

本人先前已在 LF2 官方论坛发表 [改档技术] 进阶抓人分析，本篇对 catch 时的位置变化讨论。

**一般抓人位置变化：**

- cx1 指抓人者的 centerx 值
- cx2 指被抓者的 centerx 值
- cpx1 指抓人者的 cpoint kind: 1 x 值
- cpx2 指被抓者的 cpoint kind: 2 x 值
- cd 指发生抓取时双方的距离

> 这些都是指抓人/被抓后的第一个 frame 中设定的值（由 catchingact 与 caughtact 设定的动作）。

**数字计算区：**

1. 一般「抓人者」位移：`( cx1 + cd - cpx1 - cpx2 ) / 2`（数字预设使用 template 内抓人的值）
2. 「被抓者」位置变化（c2 位移）：`cpx1 + cpx2 + ( c1 位移 ) - cx1 - cx2 - cd = - ( c1 位移 ) - cx2`
3. 将被抓者丢到原来的位置（丢掉动作的 cpoint x 值）：`cd + cx1 - ( c1 位移 )`（此 cx1 指丢掉动作的 centerx 值）

- 若设计双方的位置皆不动，即 c1 位移 = 0、c2 位移 = 0，则 cx2 的值为 0。
- 此数值以抓者在左侧，被抓者在右侧为例；位移为正值表向右移动，反之负值向左移动。

**x 方向位移（未设定 cpoint）：**

- catch_x1 指抓人者在动作（catchingact 值）的 centerx 值
- cdx 指发生抓取时双方的 x 距离
- caught_x1 指被抓者在动作（caughtact 值）的 centerx 值

「抓人者」位置变化：`( catch_x1 + cdx + caught_x1 ) / 2`
「被抓者」位置变化：`- ( catch_x1 + cdx + caught_x1 ) / 2`

**y 方向位移（未设定 cpoint）：**

「被抓者」y 位移：`cy2 - cdy - cy1`
（cy1 指抓人者的 centery 值；cy2 指被抓者的 centery 值；cdy 指双方的 y 轴距离（被抓者座标 - 抓人者座标），y 轴数值是往下递增）

## 以特定武器做专属招式

本人先前已在官坛发表以手持武器抓取自己。手持武器以 state: 18 抓自己，跳到特定动作。

> [!NOTE] 被抓的人物，速度归零、fall 值会被重置。

本教学以 template 拿轻型武器 stick 攻击时，从 frame 20、25 normal_weapon_atck 跳至 35 的 run_weapon_atck，并增加一个遥控 bdy 在地下 8000：

```text
<frame> 20 normal_weapon_atck
pic: 70  state: 3  wait: 1  next: 21  centerx: 39  centery: 79
wpoint:
kind: 1  x: 40  y: 53  weaponact: 80  attacking: 0  cover: 0
wpoint_end:
bdy:
kind: 0  x: 27  y: 20  w: 32  h: 60
bdy_end:
bdy:
kind: 0  x: 38  y: 8079  w: 2  h: 2
bdy_end:
<frame_end>

<frame> 25 normal_weapon_atck
pic: 74  state: 3  wait: 1  next: 26  centerx: 39  centery: 79
wpoint:
kind: 1  x: 51  y: 45  weaponact: 81  attacking: 0  cover: 0
wpoint_end:
bdy:
kind: 0  x: 29  y: 16  w: 29  h: 63
bdy_end:
bdy:
kind: 0  x: 38  y: 8079  w: 2  h: 2
bdy_end:
<frame_end>
```

再开启 weapon0，任意拷贝 on_hand 动作 20 为例，贴两个并修改为 80、81，state 改 18，itr kind 改为 3，并徒手新增动作 82：

```text
<frame> 80 Template_on_hand
pic: 20  state: 18  wait: 0  next: 0  centerx: 33 24  centery: 540 40
wpoint:
kind: 2  x: 24  y: 40
wpoint_end:
itr:
kind: 3  x: 22  y: 8067  w: 2  h: 2  vrest: 1  zwidth: 5
catchingact: 82  caughtact: 35
itr_end:
<frame_end>

<frame> 81 Template_on_hand
pic: 20  state: 18  wait: 0  next: 0  centerx: 22 24  centery: 548 40
wpoint:
kind: 2  x: 24  y: 40
wpoint_end:
itr:
kind: 3  x: 11  y: 8075  w: 2  h: 2  vrest: 1  zwidth: 5
catchingact: 82  caughtact: 35
itr_end:
<frame_end>

<frame> 82 on_hand
pic: -1  state: 1001  wait: 0  next: 0  centerx: -34  centery: 552
<frame_end>
```

> 以上 80 及 81 的 centerx、centery 后面那组是原始数字，前面的是修改后数字。

**开启公式：**

- 输入人物的 centerx、centery；人物的 wpoint x、y、cover
- 选择武器要变更的数值：wpoint / center
- 武器的 wpoint x、y；武器的 centerx、centery
- 希望人物与武器的中心距离（x 距离、y 距离）
- 武器在 caughtact 动作的 centerx；人物被抓动作的 centery
- 计算 → 不移动，武器抓取后的 center 应设定
- 再计算双方的距离（以 center 为中心）

**temp 动作 20 的 x 距离**（1 是武器（抓人者），2 是人物（被抓者））：

```text
cdx = cx1 - wpx1 + wpx2 - cx2
= 24 - 24 + 40 - 39
= 1
```

> 注意：若算出来是负值，表示武器的中心位置在人物中心的左边，使用抓人会转向。

本人故意将 cdx 修为正值 10（数值不要太大，跑出场边武器可能会消失）：

```text
= 33 - 24 + 40 - 39
= 10
```

将武器动作 80 的 centerx 值改为 33。

**temp 动作 25 的 x 距离：**

```text
cdx = 24 - 24 + 51 - 39
= 12
```

因为本人设计理念是为了节省 frame 之使用，故亦将距离修为 10：

```text
= 22 - 24 + 51 - 39
= 10
```

将武器动作 81 的 centerx 值改为 22。

> 提示：不一定要修改 centerx，改师们亦可选择改武器 wpoint 的 x 值，以上面公式而言是 wpx1（抓人者）。

**计算武器动作 82 的 centerx 值（被抓者 x 位移）：**

因为抓人者（武器）的动作 35 on_hand（取自 caughtact 的值 35）的 centerx 值为 24，caught_x1 = 24；若无此动作，则 caught_x1 视为 0。

```text
0 = - ( catch_x1 + cdx + caught_x1 ) / 2
0 = - ( catch_x1 + 10 + 24 ) / 2
catch_x1 = - 34
```

故武器动作 82 的 centerx 值设为 -34。

**计算双方的 y 距离（cover: 0 需加 1，cover: 1 需减 1）：**

temp 动作 20：

```text
cdy = -(cy1) + wpy1 - wpy2 + cy2 + 1
= - 40 + 40 - 53 + 79 + 1
= 27
```

temp 动作 25：

```text
cdy = - 40 + 40 - 45 + 79 + 1
= 35
```

同理，为节省 frame，将 35 修为 27：

```text
= - (48) + 40 - 45 + 79 + 1
= 27
```

武器动作 81 的 centery 暂定为 48。若将 state: 18 的 center 埋地，可以隐藏其冒烟特性。虽然本例不埋地也不会冒烟，本人还是会将武器 center 在计算后，往下增加 500，令武器中心点埋在地底下。

**计算武器动作 82 的 centery 值（y 位移）：**

temp 动作 35 的 centery 为 79，cy2 = 79。

```text
0 = 79 - 27 - cy1
cy1 = 52
```

接着将 80、82 的 centery 增加 500（往下埋 500），变成：

```text
0 = 79 - ( 27 - 500 ) - ( 52 + 500 )
（因「抓人者」往下移，相对来说，「被抓者」往上移，所以 cdy 的部分是减的）
0 = 79 - ( - 473 ) - ( 552 )
cy1 = 552
```

武器动作 82 的 centery 值设为 552。如此一来，被抓者位置不会移动。至于 itr 与 bdy 座标嘛……其原理自行理解吧……

**itr 与 bdy 座标换算：**

当人物的 bdy x: 38 时：

```text
（武器的 itr x:）=（人物的 bdy x:）-（人物的 wpoint x:）+（武器的 wpoint x:）

temp 动作 20：
38 - 40 + 24 = 22

temp 动作 25：
38 - 51 + 24 = 11
```

y 方向（cover: 0 需加 1；cover: 1 需减 1）：

```text
temp 动作 20：
8079 - 53 + 40 + 1 = 8067

temp 动作 25：
8079 - 45 + 40 + 1 = 8075
```

## 枪战系统（以 mp 作为消耗）

七夜（nanaya）的改档角色中，有一位就是以拿枪射击作为普攻：

1. 若有 mp，则射子弹。
2. 若无 mp，则进入开膛状态。

在 60、65 的动作中，加入 hit_a: ###，则 60、65 的动作中，next 指进入开膛状态的动作；hit_a 指射击动作。

> [!NOTE]
> 手持武器中加入 opoint 是可以的，手持武器是不需前置 frame 再以 next 连结就能建立物件的方式。但注意一点的是，人物的 wait 会影响建立物件的数量，一般建议将 wait 设定 0（即一个影格的时间）。

## 造人控血

造出人物后控血及动作。本人先前亦在官坛发表了造人控血。

本例为：造出 rudolf（id: 5），再以 state: 8030 变身成 bandit，再控动作至 399。

**ball：**

```text
<frame> 115 op10hpbandit_start
pic: -1  state: 15  wait: 0  next: 116
<frame_end>

<frame> 116 op
pic: -1  state: 15  wait: 2  next: 117
opoint:
kind: 2  x: 0  y: 0  action: 310  oid: 5
opoint_end:
wpoint:
kind: 1  x: -39  y: -78  weaponact: 310
wpoint_end:
<frame_end>

<frame> 117 op_ed
pic: -1  state: 15  wait: 2  next: 1000
wpoint:
kind: 1  x: -39  y: -78  weaponact: 399
wpoint_end:
<frame_end>
```

**rudolf（id: 5）：**

```text
<frame> 310 tran_bandit
pic: -1  state: 8030  wait: 2  next: 999
<frame_end>
```

> 虽然也有人想过直接用 rudolf 抓人变身，此方法就不用换图，但是有电脑还是会不小心按到 DJA，变回 rudolf，就变成了要设计「先变成某只角色，再变身指定角色」。由于设计过程复杂，因此不便介绍。

有些人会想设计在闯关放入 hp: 0 的角色，除了直接在 stage 中输入 hp: 0 外，另一种是攻击扣血：

**ball：**

```text

pic: -1  state: 15  wait: 0  next: 116
<frame_end>

<frame> 116 hpto0

kind: 2  x: 0  y: 0  action: 390  oid: 41
opoint_end:
wpoint:
kind: 1  x: 0  y: 1  weaponact: 390
wpoint_end:
itr:
kind: 0  x: -5  y: 1000  w: 10  h: 10  vrest: 20  injury: 500
itr_end:
<frame_end>

<frame> 117 act_ed
pic: -1  state: 15  wait: 2  next: 1000
wpoint:
kind: 1  x: -39  y: -78  weaponact: ###
wpoint_end:
<frame_end>
```

**（id: 41）：**


> 因 hp 被打到 0 会有 x y 速度，用 dvx 和 dvy 550 归零其速度。
